Date Spines and CROSS JOINs

SQL notes · clinical toy data · every day on the calendar, zeros included

The idea. Real event tables have gaps — no row exists for days nothing happened. A plain GROUP BY day then lies by omission: quiet days vanish instead of showing zero. The fix is a date spine (a complete calendar you build yourself), optionally crossed with your categories, with the events LEFT JOINed on.

The naive version — and what it hides

SELECT visit_date AS day, COUNT(*) AS visits
FROM ed_visits GROUP BY visit_date ORDER BY day;
dayvisits
2024-01-022
2024-01-041
2024-01-071

Three rows. The other 28 days of January simply don't exist here — any chart drawn from this is missing most of the month.

Step 1: build the spine (recursive CTE)

WITH RECURSIVE spine(d) AS (
  SELECT date('2024-01-01')
  UNION ALL
  SELECT date(d, '+1 day') FROM spine WHERE d < '2024-01-31'
)\nSELECT d FROM spine;  -- 31 rows

Start at Jan 1, keep adding a day until Jan 31. (Dialect note: BigQuery spells this GENERATE_DATE_ARRAY; the idea is identical.)

Step 2: CROSS JOIN the grid — every day × every department

WITH RECURSIVE spine(d) AS (
  SELECT date('2024-01-01')
  UNION ALL
  SELECT date(d, '+1 day') FROM spine WHERE d < '2024-01-31'
),
depts AS (SELECT DISTINCT department AS dept FROM ed_visits)
SELECT s.d, x.dept FROM spine s CROSS JOIN depts x ORDER BY s.d, x.dept;

CROSS JOIN is the full multiplication: 31 days × 2 departments = 62 rows. This grid is the skeleton your facts hang on.

Step 3: LEFT JOIN the events onto the grid

WITH RECURSIVE spine(d) AS (
  SELECT date('2024-01-01')
  UNION ALL
  SELECT date(d, '+1 day') FROM spine WHERE d < '2024-01-31'
),
depts AS (SELECT DISTINCT department AS dept FROM ed_visits)
SELECT s.d AS day, x.dept AS department, COUNT(v.visit_date) AS visits
FROM spine s CROSS JOIN depts x
LEFT JOIN ed_visits v ON v.visit_date = s.d AND v.department = x.dept
GROUP BY s.d, x.dept ORDER BY s.d, x.dept;

Watch out.
  • COUNT(v.visit_date), not COUNT(*) — after a LEFT JOIN, COUNT(*) counts the empty joined rows as 1 and your zeros become ones.
  • Put the category match (v.department = x.dept) in the ON clause, not WHERE — WHERE filters after the join and kills your zero rows.
  • CROSS JOIN multiplies: sanity-check the grid size (days × categories) before joining facts onto it.
Prove it. Every query on this page was run against SQLite and the tables show actual output — not hand-typed guesses.
