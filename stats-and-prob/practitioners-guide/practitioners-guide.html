The setup: null vs alternative, α, and tails

Every test on this page is the same argument. The null hypothesis (H0) says nothing is going on — no difference, no effect, the benchmark is right. The alternative hypothesis (HA) is the thing you're trying to show. You assume H0 is true, then ask: if it were, how surprising is my data? That surprise is the p-value: the probability of seeing data at least this extreme if H0 were true.

The significance level (α) is your surprise threshold, set before looking at the data — 0.05 is the convention. If p ≤ α, you reject H0; if p > α, you fail to reject it (more on that phrasing in the courtroom section — it matters).

Tails are where HA points. Two-tailed: a difference in either direction counts (the default — safest, and what you should use unless you committed in advance). Right-tailed: only "more than" counts. Left-tailed: only "less than" counts. Choosing the tail after seeing the data is cheating: it quietly doubles your false-alarm rate.

z-scores & test statistics: one idea behind every test

A z-score measures distance in units of noise: z = (what you saw − what H0 expects) / standard error. Saw a sample mean of 104 when H0 says 100, with a standard error of 1.5? That's z = 2.7 — your result sits 2.7 noise-units away from "nothing going on." The further out, the smaller the p-value.

Every test statistic on this page — t, F, χ², U, H — is that same move with different plumbing: distance from H0, divided by how much wobble you'd expect by chance. Learn to read one and you can read them all. Field rule of thumb: a statistic around 2 standard errors from the null is roughly the p = 0.05 line for two-tailed tests.

The decision rule: guilty beyond a reasonable doubt

A hypothesis test is a criminal trial. The defendant is H0 — "no effect" — and the defendant is presumed innocent. The data is the evidence. Your α is the standard of proof: guilty beyond a reasonable doubt.

Reject H0 = a guilty verdict: the evidence is too strong to be a coincidence.

Fail to reject H0 = a "not guilty" verdict — which is not a declaration of innocence. It means the evidence wasn't strong enough. That's why statisticians never say "accept H0" or "we proved there's no effect": absence of evidence is not evidence of absence. Your study may simply have been too small to see what was there (that's β).

The two errors map too: a Type I error convicts an innocent defendant; a Type II error lets a guilty one walk. Tighten the standard of proof (smaller α) and you convict fewer innocents — but more of the guilty walk free. α = 0.05 is a convention for balancing the two, not a law of nature.

Comparing means

z-test (one sample, known σ)

Use it when: you're comparing a sample mean to a known benchmark and you genuinely know the population standard deviation σ — usually because a huge reference dataset or a calibrated instrument pinned it down.

Example: a reference lab has measured fasting glucose for years: population mean 100 mg/dL, σ = 12 known from quality-control data. A new clinic's 64 patients average 103.7 mg/dL. Different population, or just noise? z = 2.44, p = 0.015 → reject H0 at α = 0.05.

Assumptions: σ truly known; independent observations; sample mean roughly normal (data normal, or n ≥ ~30).

Reality check: σ is almost never known in real work — that's why the t-test below is the everyday tool. The z machinery's main modern jobs are proportions (further down) and large-sample approximations.

Data structure + Python code

Data: one sample summarized by its mean, plus the known σ. The course-style way — build the p-value by hand from the normal CDF:

import numpy as np
from scipy.stats import norm

xbar, mu0, sigma, n = 103.7, 100, 12, 64   # sample mean, H0 value, KNOWN sd, sample size
z = (xbar - mu0) / (sigma / np.sqrt(n))       # = 2.44
p = 2 * (1 - norm.cdf(abs(z)))                # two-tailed: double the upper tail
# left-tailed test:  p = norm.cdf(z)
# right-tailed test: p = 1 - norm.cdf(z)

Output: z = 2.44, p = 0.015.

One-sample t-test

Use it when: one sample mean vs a benchmark, and σ is unknown — the normal real-world case. The t distribution is the normal with fatter tails, charging you for having to estimate the spread from the same data.

Example: HbA1c for 25 patients at a diabetes clinic averages 7.54% against a target of 7.0%. T = 3.30, p = 0.003 → reject H0: the clinic's patients run above target.

Assumptions: independent observations; data roughly normal, or n ≥ ~30 (the t-test tolerates mild skew at moderate n).

If that fails (small n, clearly skewed): the one-sample Wilcoxon signed-rank test against the benchmark value.

Data structure + Python code

Data: one column of numbers (here, a NumPy array of HbA1c values).

import pingouin as pg

# a1c: array of 25 HbA1c values, mean 7.54
pg.ttest(x=a1c, y=7.0)        # y = the benchmark value under H0

Key output: T = 3.30, dof = 24, p = 0.003.

Two-sample t-test

Use it when: comparing the means of two independent groups.

Example: length of stay under a new discharge protocol (35 patients, mean 4.1 days) vs standard care (35 patients, mean 5.5 days). T = -4.83, p < 0.001 → reject H0: the new protocol's stays are shorter.

Assumptions: the two groups are independent; each group roughly normal or n ≥ ~30 per group. You do not need equal variances — use Welch's version (pingouin's default behavior), which adjusts for unequal spreads.

If that fails (heavy skew — and length of stay is famously skewed, so in real work you may land here directly): the Mann-Whitney U test.

Data structure + Python code

Data: two columns/arrays, one per group.

import pingouin as pg

pg.ttest(x=los_new, y=los_std)   # Welch's correction applied automatically

Key output: T = -4.83, p < 0.001.

Paired t-test

Use it when: the same subjects are measured twice — before/after, or matched pairs. The test runs on the differences, one per subject.

Example: systolic blood pressure in 20 patients before (mean 142 mmHg) and after (mean 136 mmHg) a 12-week hypertension program. T = -3.06, p = 0.006 → reject H0: blood pressure dropped.

Why pairing is powerful: each patient is their own control, so the large person-to-person variation cancels out of the comparison. Assumptions: the differences are roughly normal (not the raw values); pairs are independent of each other.

If that fails (differences skewed, or the outcome is ordinal): the Wilcoxon signed-rank test.

Data structure + Python code

Data: two aligned columns — row i is the same patient in both.

import pingouin as pg

pg.ttest(x=bp_after, y=bp_before, paired=True)

Key output: T = -3.06, dof = 19, p = 0.006.

ANOVA (one-way)

Use it when: comparing means across three or more groups with a single test. ANOVA answers only "does any group differ?" — not which ones.

Example: weight loss at 3 months across four programs — diet only (mean 2.3 kg), diet + exercise (3.8), medication (5.0), medication + exercise (7.6), 16 patients each. F = 30.1, p < 0.001 → reject H0: the programs are not all equal. Which ones differ is the next section's job.

Assumptions: independent observations; roughly normal within each group (or decent n per group); roughly similar spreads across groups.

If that fails: the Kruskal-Wallis test.

Data structure + Python code

Data: a long-format table — one row per patient, a value column and a group column.

import pingouin as pg

# df: columns 'loss' (kg) and 'program' (4 labels), 64 rows
pg.anova(data=df, dv='loss', between='program')

Key output: F = 30.1, p < 0.001.

Pairwise comparisons + Bonferroni correction

Use it when: ANOVA says "something differs" and you need to know which pairs of groups differ.

The trap: four programs make 6 pairwise tests. Run each at α = 0.05 and the chance of at least one false alarm isn't 5% — it's about 26% (1 − 0.956). Every extra test is another lottery ticket for a fluke. Running many t-tests instead of ANOVA + corrected pairwise tests is exactly this mistake.

The Bonferroni fix: multiply each p-value by the number of tests (equivalently, judge each against α/6 ≈ 0.008). Simple, a bit conservative, and the right default. On the weight-loss data:

  Diet + exercise vs Diet only:  p = 0.014  ->  Bonferroni p = 0.083
  Diet + exercise vs Medication:  p = 0.070  ->  Bonferroni p = 0.418
  Diet + exercise vs Medication + exercise:  p = 0.000  ->  Bonferroni p = 0.000
  Diet only vs Medication:  p = 0.000  ->  Bonferroni p = 0.000
  Diet only vs Medication + exercise:  p = 0.000  ->  Bonferroni p = 0.000
  Medication vs Medication + exercise:  p = 0.000  ->  Bonferroni p = 0.001

The strongest gap (diet only vs medication + exercise) survives the correction easily; the correction costs you the borderline pairs — that's the price of honesty.

Data structure + Python code

Data: the same long-format table as ANOVA.

import pingouin as pg

pg.pairwise_tests(data=df, dv='loss', between='program', padjust='bonf')
# read the p_corr column: already Bonferroni-adjusted

Proportions & categories

One-sample proportion test

Use it when: one observed rate vs a published benchmark rate.

Example: 14 surgical-site infections in 200 surgeries (7.0%) vs a published benchmark of 5%. z = 1.11, p = 0.268 → fail to reject H0. Read that the courtroom way: not proof our rate is 5% — just not enough evidence to say it differs.

Why z here, not t? A proportion carries its own standard error: SE = √(p(1−p)/n). There's no separate spread to estimate from the sample the way a mean forces you to estimate σ — and it's estimating σ that earns the t distribution its fatter tails. With the SE coming from the proportion itself, the plain normal (z) is the right reference, once n is large enough for the normal approximation to the binomial.

Assumptions: independent cases; np and n(1−p) both ≥ ~10 under the benchmark p.

If n is too small: the exact binomial test (scipy.stats.binomtest) — same question, no normal approximation.

Data structure + Python code

Data: just two counts — how many events, out of how many trials.

from statsmodels.stats.proportion import proportions_ztest

proportions_ztest(count=14, nobs=200, value=0.05)   # value = benchmark under H0

Output: z = 1.11, p = 0.268.

Two-sample proportion test

Use it when: comparing a rate between two groups.

Example: 30-day readmissions: 15 of 150 patients (10%) on a new follow-up program vs 32 of 160 (20%) on standard care. z = -2.45, p = 0.014 → reject H0: the program's readmission rate is lower.

Assumptions: independent groups; each cell count ≥ ~10. Worth knowing: this test is mathematically the same as a chi-squared test of independence on the 2×2 table — two doors into the same room.

Data structure + Python code

Data: two counts and two totals, as arrays.

import numpy as np
from statsmodels.stats.proportion import proportions_ztest

proportions_ztest(count=np.array([15, 32]), nobs=np.array([150, 160]))

Output: z = -2.45, p = 0.014.

Chi-squared test of independence

Use it when: two categorical variables, and you're asking whether they're associated. In one line: compare the counts you observed with the counts you'd expect if the variables were independent — big gaps make a big χ².

Example: smoking status vs COPD diagnosis in a screening sample of 500: smokers 45 COPD / 155 no COPD; non-smokers 20 / 280. χ² = 25.2, p < 0.001 → reject H0: smoking and COPD are associated. (Associated — not proven causal; that's a design question, not a test question.)

Assumptions: work with counts, never percentages; independent observations; the expected count is ≥ 5 in every cell (here the smallest expected count is 26).

If expected counts are too small (2×2 table): Fisher's exact test.

Data structure + Python code

Data: a long-format table — one row per person, one column per categorical variable.

import pingouin as pg

# df: 500 rows; columns 'smoker' (Smoker / Non-smoker) and 'copd' (COPD / No COPD)
expected, observed, stats = pg.chi2_independence(data=df, x='smoker', y='copd')

Key output (pearson row): χ² = 25.2, p < 0.001.

Chi-squared goodness-of-fit test

Use it when: one categorical variable, and you're asking whether observed counts match a hypothesized distribution.

Example: 1100 emergency-department arrivals across a week — Mon 205, Tue 160, Wed 150, Thu 152, Fri 158, Sat 135, Sun 140 — against a uniform expectation of ~157 per day. χ² = 20.1, p = 0.003 → reject H0: arrivals are not spread evenly; Mondays spike.

Assumptions: counts, not proportions; expected count ≥ 5 in every category.

Data structure + Python code

Data: two aligned lists — observed counts and expected counts (same total).

from scipy.stats import chisquare

chisquare(f_obs=[205, 160, 150, 152, 158, 135, 140],
          f_exp=[157.1, 157.1, 157.1, 157.1, 157.1, 157.1, 157.1])

Output: χ² = 20.1, p = 0.003.

When the assumptions break: rank tests

The three tests below don't use the raw values at all — they convert everything to ranks (1st, 2nd, 3rd…) and test those. Skew and outliers can't bully a rank, and ordinal scores (pain 0–10, satisfaction 1–10) are welcome. The trade: slightly less power when the data really are normal. Each one is the fallback for a test above.

Wilcoxon signed-rank test

Use it when: paired data (before/after) whose differences are skewed — or an ordinal outcome. The paired t-test's fallback; a one-sample version also tests against a benchmark. In one line: rank the sizes of the differences, then check whether the positive and negative ranks balance.

Example: pain scores (0–10) before and after physical therapy for 14 back-pain patients — an ordinal scale, so ranks, not means. W = 0, p = 0.002 → reject H0: pain dropped. (W = 0 is as one-sided as it gets: every patient's pain went down.)

Data structure + Python code

Data: two aligned arrays — row i is the same patient in both.

import pingouin as pg

pain_before = [8, 7, 9, 6, 8, 7, 9, 8, 6, 7, 8, 9, 7, 8]
pain_after  = [5, 6, 6, 5, 4, 7, 6, 5, 6, 4, 5, 7, 5, 6]
pg.wilcoxon(x=pain_before, y=pain_after)

Key output: W = 0, p = 0.002.

Mann-Whitney U test

Use it when: two independent groups and a skewed outcome or ordinal scores. The two-sample t-test's fallback. It asks whether a random patient from one group tends to rank above a random patient from the other — so report medians alongside it.

Example: wait times at two clinics (minutes, heavily right-skewed): median 32 at Clinic A vs 40 at Clinic B, 28 patients each. U = 266, p = 0.040 → reject H0: the waits genuinely differ.

Data structure + Python code

Data: two arrays, one per group.

import pingouin as pg

pg.mwu(x=wait_a, y=wait_b)

Key output: U = 266, p = 0.040.

Kruskal-Wallis test

Use it when: three or more groups, skewed outcome or ordinal scores — ANOVA's fallback. (Same relationship as Mann-Whitney to the t-test: Kruskal-Wallis is to Wilcoxon-Mann-Whitney what ANOVA is to the t-test.)

Example: patient satisfaction (1–10) across four clinics, 18 patients each. H = 16.5, p < 0.001 → reject H0: the clinics differ. Follow up with pairwise Mann-Whitney tests plus a Bonferroni correction, exactly as in the pairwise section.

Data structure + Python code

Data: a long-format table — one row per patient, score column + clinic column.

import pingouin as pg

# df: columns 'score' (1-10) and 'clinic' (A/B/C/D), 72 rows
pg.kruskal(data=df, dv='score', between='clinic')

Key output: H = 16.5, p < 0.001.
